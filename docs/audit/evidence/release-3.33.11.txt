# Release evidence — v0.9.0-gui3.33.11

Tag: v0.9.0-gui3.33.11
Purpose: ship a native Arch Linux package and make the app's own update button
update it, with polkit when available and a copyable command when it is not.

## What changed

- New release asset `proton-drive-0.9.0+gui3.33.11-1-x86_64.pkg.tar.zst`.
  It installs the tested payload natively under `/usr` (GUI, engine, official
  CLI, dispatcher, desktop entry, AppStream metadata, icons and licences).
  There is no AppImage and no FUSE requirement.
- The package ships `proton-sync.service` in systemd's vendor directory and a
  `/usr/lib/proton-drive/package` marker. The GUI now finds the vendor unit, so
  Start, Pause and Start-at-login work in a native install.
- With the marker present, **Download and restart** downloads the release's
  `.pkg.tar.zst`, verifies it against the signed `SHA256SUMS`, and runs
  `pacman -U` through `pkexec` (polkit password dialog). Without a polkit agent
  or a dismissed prompt, the verified archive stays on disk and the app shows
  the exact `sudo pacman -U …` command with a Copy button.
- AppImage installs keep the AppImage self-update path even if the Arch package
  is also installed (the running format decides).

## Verification

`scripts/verify-release.sh v0.9.0-gui3.33.11` downloaded the published release
and reported:

- `signature: SHA256SUMS OK` and `signature: revocations.json OK`.
- x86_64 smoke: `gui 3.33.11`, CLI reachable, health status `ok`.
- GLIBC floor 2.28 for AppRun, GUI and engine on both AppImages, and for the
  GUI and engine inside the Arch package.
- Both `.deb` files install the tested AppImage; the Flatpak bundle and the
  Arch package are present and well formed.

The published Arch package was installed into a disposable pacman root
(`pacman -Udd --root …`): installed cleanly, `/usr/lib/proton-drive/package`
contains `arch`, and `pacman -Qip` reports version
`0.9.0+gui3.33.11-1`, architecture `x86_64`, installed size 120.77 MiB.

In a user namespace with the package's files overlaid on `/usr`:

- `proton-drive --version` reached the official CLI through the dispatcher.
- `systemd-analyze verify` accepted the vendor unit and its `ExecStart`.
- `PROTON_SYNC_SMOKE=1 proton-drive --smoke` reported
  `smoke ok: gui 3.33.11, conf keys 15, cli true, health status 'ok'`.

## Limits

- The live polkit password dialog was not automated: it needs an interactive
  desktop session and a newer release than the one being installed. The
  download, signed-manifest verification, asset selection and install command
  are covered by tests; the first package-to-package update will be 3.33.12.
- A custom `XDG_CONFIG_HOME`/`XDG_STATE_HOME` is not carried into the vendor
  unit (it uses the systemd `%h` defaults). Default Arch desktops are unaffected.
