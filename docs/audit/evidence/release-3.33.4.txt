# Release evidence — v0.9.0-gui3.33.4

Tag: v0.9.0-gui3.33.4
Purpose: stop the repeated "1 file(s) uploaded" notification caused by the
photo pass restoring a stale file-cycle health snapshot.

## Root cause

`run_photos` copies the current health, sets `phase = "photos"`, runs the
photo pass, then restores the snapshot. That snapshot can still contain
`uploaded = 1` from the last real file upload. The GUI's transition check saw:

```
syncing → ok, uploaded = 1, phase = photos
```

and fired the "All done — 1 file(s) uploaded" notification again, even though
no file was uploaded. Photo requests every few minutes made it repeat.

## Fix

`done_notification(previous, health)` now requires:

- `previous == "syncing"`
- `health.status == "ok"`
- `health.phase == None` (a real file cycle, not the photo restore)
- at least one uploaded/downloaded file

Regression test covers the photo-phase snapshot, a normal completion and a
non-transition.
