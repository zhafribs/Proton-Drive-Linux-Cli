# Release evidence — v0.9.0-gui3.33.13

Tag: v0.9.0-gui3.33.13
Purpose: make Colors → "My system" follow the desktop palette immediately,
from whatever file the wallpaper tool writes.

## What changed

- **No filename is special.** The palette reader used to try
  `gtk-4.0/noctalia.css`, `gtk-3.0/noctalia.css` and the two stock `gtk.css`
  files. It now scans every `*.css` in `~/.config/gtk-4.0` and then
  `~/.config/gtk-3.0`, newest first, and takes the first file that carries the
  complete token set (`accent_*`, `window_bg_color`/`view_bg_color`,
  `card_bg_color`/`popover_bg_color`, `window_fg_color`/`view_fg_color`).
  - A stock `gtk.css` that is only `@import url("...")` parses to nothing and
    is skipped; the imported file is found by the scan.
  - After switching palette tools, the file just generated wins over the old
    tool's leftover, because files are ordered by modification time.
  - Tools covered in practice: Noctalia, matugen, pywal's GTK template,
    Gradience, caelestia, end-4's templates and ML4W — all write GTK CSS,
    under different names.
- **Immediate repaint.** An inotify watch on the two GTK config directories
  wakes the UI on any `*.css` create/write/rename. The 30-second theme poll
  stays as the safety net, and when inotify cannot watch, a one-second
  re-read-and-compare loop replaces it.
- The Settings hint under Colors now names the tools generically.

## Limits

- Only GTK CSS is read. A setup that generates no GTK colours (for example a
  scheme kept solely in JSON/Hyprland config) still falls back to Proton
  colours; adding a second format would need its own parser and tests.
- The watch covers the two GTK directories that exist when the app starts. A
  directory created later is picked up by the 30-second theme tick.
