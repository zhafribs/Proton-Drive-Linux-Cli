# Release evidence — v0.9.0-gui3.33.1

Tag: v0.9.0-gui3.33.1
Purpose: fix the remote rename/move bug that turned the status red after a
local folder rename or cross-folder move.

## Root cause

`Action::MvRemote` called:

```
fs move <old> <target-parent> <new-name>
```

The official CLI's verbs are:

```
filesystem move PATH... PARENT     # keeps the basename
filesystem rename PATH NAME        # changes the basename
```

The third argument was rejected with `Path "<name>" not supported`. The engine
marked both the old and new path as failed, so `health.failed` became 2 and the
status turned red even though the files were safe. Restarting or resyncing
retried the same rejected command.

## Fix

- Rename-only: `fs rename <old> <new-name>`.
- Parent change only: `fs move <old> <new-parent>`.
- Both: `fs move`, then `fs rename <new-parent>/<old-name> <new-name>`.
- Failure logs the actual CLI error and marks both paths failed.

Regression tests assert the exact argument order for rename-only and
cross-folder move+rename.
